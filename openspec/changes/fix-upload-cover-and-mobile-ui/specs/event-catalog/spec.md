## Purpose

定义事件（Event）目录对员工端的可读性：员工端活动筛选需要一个可读的事件列表，而事件的增删改仍必须保持管理端专属。

## ADDED Requirements

### Requirement: 员工可读取事件列表

已认证员工 SHALL 能够读取事件列表（用于活动筛选「所属事件」下拉），该读取能力 MUST NOT 要求管理员角色。

#### Scenario: 员工打开活动列表页

- **WHEN** 已登录员工访问 `/activities`
- **THEN** 页面请求事件列表返回成功状态码，且「所属事件」下拉在有事件数据时非空

#### Scenario: 员工无事件列表权限时的表现

- **WHEN** 因任何原因事件列表读取失败
- **THEN** 活动列表本身仍可正常展示与筛选，失败不阻塞主流程且控制台不出现未捕获错误

### Requirement: 事件写操作保持管理端专属

事件的创建、更新、删除 SHALL 仅对管理员开放；放宽读权限 MUST NOT 放宽写权限。

#### Scenario: 员工尝试写入事件

- **WHEN** 员工令牌调用事件创建/更新/删除接口
- **THEN** 返回 403，事件数据不发生变更
