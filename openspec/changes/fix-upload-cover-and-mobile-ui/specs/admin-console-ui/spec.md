## Purpose

定义管理端（`/admin/**`）表单抽屉与操作反馈的可用性契约：抽屉的提交动作在任何内容长度与移动视口下都必须可达，任何操作失败都必须产生用户可见的反馈。

## ADDED Requirements

### Requirement: 抽屉页脚在内容超长时保持可见

管理端表单/详情抽屉 SHALL 采用「固定头部 + 可滚动主体 + 固定页脚」的布局：主体内容超出视口高度时只有主体滚动，页脚（取消/保存等提交动作）MUST 始终可见且可点击。

#### Scenario: 抽屉内容超长

- **WHEN** 打开「新建事件」「新建活动」或任一详情抽屉，并使表单内容高度超过视口
- **THEN** 主体区域出现独立滚动，页脚的提交按钮仍在视口内可点击

#### Scenario: 移动视口下的抽屉

- **WHEN** 以 390×844 视口打开上述任一抽屉
- **THEN** 抽屉宽度等于视口宽度、不产生横向滚动，页脚按钮完整可见

### Requirement: 操作失败必须给出可见反馈

管理端在抽屉打开状态下发生的失败（校验不通过、文件超限、接口报错、请求被拒绝）SHALL 以用户可见的方式呈现，提示元素 MUST 绘制在抽屉之上，不得被抽屉面板遮挡。

#### Scenario: 打开抽屉时提交失败

- **WHEN** 在抽屉打开状态下提交表单且后端返回错误，或所选文件超出限制
- **THEN** 用户能看到明确的失败信息（文案包含失败原因），而不是界面无任何变化

### Requirement: 封面图上传的前端约束与反馈

管理端上传活动/事件封面图时，系统 SHALL 在上传前对图片做尺寸与体积处理，并在以下情形给出可见且有区分度的反馈：文件类型不支持、处理失败、超出服务端可接受的请求体积。上传成功后 MUST 立即显示预览。

#### Scenario: 上传超限图片

- **WHEN** 用户选择一个超出体积上限的图片文件
- **THEN** 界面立即显示明确的超限提示，且不会以无反馈的方式静默丢弃

#### Scenario: 上传常见手机照片

- **WHEN** 用户选择一张常见手机拍摄尺寸（数 MB）的图片并保存活动
- **THEN** 请求体积被压缩到服务端与反代上限之内，保存成功且列表/详情能正常显示该封面

#### Scenario: 上传后立即预览

- **WHEN** 用户选择一张合法图片
- **THEN** 抽屉内立即出现该图片的预览，并可通过删除按钮清除后重新选择
