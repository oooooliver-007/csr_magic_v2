## MODIFIED Requirements

### Requirement: 登录失败必须显示明确错误信息

用户使用错误密码或不存在用户名登录时，系统必须向后端发起登录请求并展示后端返回的错误信息（如「用户名或密码错误」），不得因前端拦截器吞掉 401 而无任何提示。前端 API 拦截器仅对携带 Authorization 请求执行 401→Token 刷新逻辑；匿名请求（如登录、注册）的 401 必须直接返回调用方。

#### Scenario: 密码错误显示错误信息
- **WHEN** 用户提交的用户名存在但密码错误
- **THEN** 登录请求返回 401，页面在表单上方显示后端错误信息（如「用户名或密码错误」），不跳转、不清除登录状态

#### Scenario: 用户名不存在显示错误信息
- **WHEN** 用户提交不存在的用户名
- **THEN** 页面显示「用户名或密码错误」提示，不跳转

#### Scenario: 连续失败触发账户锁定提示
- **WHEN** 用户连续 5 次登录失败后再次尝试
- **THEN** 页面显示后端返回的「账户已被锁定，请稍后再试」提示

#### Scenario: 已认证请求 401 仍走刷新
- **WHEN** 一个携带 Authorization 头的已认证请求返回 401
- **THEN** 前端仍执行既有的 Token 刷新流程，行为保持不变

#### Scenario: 表单校验失败不发起请求
- **WHEN** 用户提交空用户名或空密码
- **THEN** 页面本地校验提示「用户名不能为空」/「密码不能为空」，不发起登录请求
